SiteKPI 기획서

GA4 숫자를 「좋다·나쁘다」로 바로 읽게 해 주는 보드. 화면 문구는 일본어(ja)가 기준이고 en·ko도 같은 구조로 나온다. 개발 사양(API·데이터·코드 구조)은 docs/SPEC.md.

목적과 대상

GA4를 연결하고 5분 안에 「우리 사이트가 업계보다 좋은가, 지난 기간보다 나아졌는가」라는 지금의 사실을 알게 한다.
대상들어오는 이유꼭 얻어 가야 하는 것
초보 운영자 (1인 사업자, 마케팅 신입)GA4 화면이 어렵다지금 볼 숫자 몇 개와 그 뜻 (한 줄 판정)
운영 중인 사이트 담당자주간·월간 보고, 개선 포인트 찾기같은 숫자 위에 업계·전기·이탈 구간이 붙어 있는 상태
컨설턴트·에이전시여러 고객 사이트 비교같은 틀로 본 비교 가능한 숫자

보드는 「질문의 깊이」 순서

사람을 초보·중급으로 나누지 않는다. 한 페이지 안에서 아래로 내려갈수록 깊어진다.

층답하는 질문보이는 것
いまの状態괜찮은가?판정 한 문장 + 타일 3개(주전환 건수 · 주전환율 · 一番の課題). 전기·업계는 말로(「前期 +4.2%」「目安内」)
どこで離れているか어디서 새는가?흐름(가로 퍼널, 막대 = 온 사람의 %) · 一番の離脱 · 今見るべきこと · 流入別
詳しい数字왜? 근거는?8 카테고리를 세로로. 한 줄 = 지표 · 값 · 8주 추이 · 전기 대비 · 업계 目安·차이 · 판정

설계 원칙

  • 숫자 먼저, 설정은 그다음. 연결하면 설정 없이 바로 보드. 흐름·업종은 추측해서 「仮」로 보여 주고, 숫자를 본 뒤에 고치게 한다.
  • 흐름은 행동이, 기준은 업종이 정한다. 사용자가 고르는 축은 둘뿐(訪問者の行動 × 比べる業種). 행동은 업종을 모르고, 업종은 흐름을 모른다.
  • GA4 기본부터. 모든 흐름은 サイトに来た → サイトを開いた(session_start) → しっかり見た(user_engagement)로 시작한다.
  • 근거 없는 숫자로 판정하지 않는다. 출처 있는 기준만 「業界目安」. 정의가 다르면 비교하지 않고 「基準なし」.
  • 두 잣대를 같은 줄에. 業界目安(바깥)과 前期比(안쪽)를 함께 보여 준다.
  • 설정 페이지를 따로 두지 않는다. 고치기는 보드 안(편집 모드·드로어)에서. 옛 /setup 주소는 보드로 보낸다.

하지 않는 것

  • 초보용 / 중급용으로 메뉴·제품을 둘로 나누지 않는다.
  • 설정 단계(흐름·업종·조정)를 통과해야 숫자를 보여 주는 입구를 만들지 않는다.
  • 한 화면에 이벤트 ID·팁·표 전체를 쑤셔 넣지 않는다(보충은 「説明」).

전체 규칙

화면에는 「숫자·판정·한마디」만

계산식·출처·전기 내역·보는 포인트·주의 문구는 모두 「説明」 팝업으로 보낸다.

겹쳐 여는 것은 2종류만

작은 보충 = 「説明」 팝업 / 고르기·고치기 = 오른쪽 위 드로어(비교 업종·흐름의 단). 둘을 동시에 겹치지 않는다.

판정은 색 + 글자

良好·目安内·要注意 를 항상 글자로 함께. 오렌지 = 악화, 틸 = 개선, 파랑 = 조작과 기준.

휴대폰 화면은 일단 제외

PC(폭 1440)를 기준으로 설계한다. 좁은 화면은 깨지지 않을 정도만.

진행 방식

  1. 1고친다화면은 디자인 캔버스(「SiteKPI 新デザイン」)에서, 규칙·결정은 이 기획서에서 고친다.
  2. 2「반영해줘」코드에 반영하고, 같은 때에 캔버스 화면을 screens/로 복사·결정을 해당 화면에 ✓ 한 줄 추가. 테스트·SPEC.md 도 함께.
  3. 3스크린샷으로 확인구현 화면을 기획서 화면과 나란히 보고 다시 1로.

화면 설계의 원본은 디자인 캔버스. screens/는 그 사본이며 같은 형식이라 브라우저로 그대로 열린다(screens/support.js가 그림). 아래 미리보기 안의 버튼도 실제로 눌린다.

03ボード/live

상단 바

  • 사이트명·비교 업종·기간·페이지 내 메뉴(いまの状態 / どこで離れているか / 詳しい数字 + 要注意 수)는 스크롤해도 따라온다.
  • 오른쪽은 ［比べる業種 ▾］［期間 ▾］ 두 개만.
  • 기간바꾸면 그 기간으로 보드를 다시 읽는다(?period=). 흐름을 저장해도 기간은 유지.
  • 비교 업종독립 페이지 없이 오른쪽 위 드로어. 상단 바·目安의 「説明」에서 연다. 드로어 맨 아래 「目安を細かく調整」: 누르면 드로어를 닫고 業種 버튼 아래에 目安 조정 팝업을 연다(겹치지 않음).

알아차리게 하기

  • 첫 안내에 임시로 정한 2가지를 버튼과 함께: 「流れ 買う ✎直す」「比べる業種 EC・小売 変える▾」「このままでよい」.
  • 기록 없는 단에는 그 자리에 「サイトのイベント名が違うかも」+「✎ この段を直す」(편집 모드 + 그 단의 드로어).
  • 目安과 크게 다를 때(目安 폭 이상 벗어난 지표가 있거나 要注意가 2개 이상) 今見るべきこと 아래에 「業種を変える▾」.

どこで離れているか · 흐름 고치기

  • 흐름 설정은 독립 페이지 없이 이 영역을 편집 모드로 바꿔서 고친다. 「流れを直す」는 제목·「説明」 바로 옆.
  • 단을 누르면 오른쪽 위 드로어(이름·이벤트·삭제). 아래에 「この段にする」「保存」을 고정(드로어가 편집 바의 저장을 가리므로).
  • 편집 모드의 인원은 보드 흐름과 같은 숫자(같은 기간). 드로어의 이벤트 목록은 사이트 기록 수 그대로.

詳しい数字

  • 탭 없이 한 줄에 한 카테고리로 세로로. 업계 目安은 행에 표시, 각 행에 8주 추이.
  • 추가 수치: 売上·デバイス(새 카테고리), 新規/再訪·DAU/MAU·平均セッション時間·イベント/セッション·スクロール·DL·キーイベント·セッションCVR, 채널별 세션 수와 CVR.
  • 잘 안 보는 카테고리(オーディエンス·イベント)는 처음엔 접고 상위 3개를 한 줄로.
  • 로딩: いまの状態·どこで離れているか 를 먼저, 詳しい数字는 나중에(도착할 때까지 회색 띠).
미리보기 안에서 스크롤·클릭 가능: 「変える▾」→ 업종 드로어 · 「流れを直す」→ 편집 모드 · 「説明」→ 팝업새 창에서 열기 ↗

첫 추측 (숫자 먼저)

연결 직후 아직 아무것도 고르지 않았으면, 사이트의 GA4 이벤트로 행동과 업종을 추측해서 바로 보드를 연다.

  • 행동사이트가 기록하는 주전환 이벤트 중 우선순위가 높은 것: purchase > sign_up > form_submit > video_complete > click. 같으면 흐름의 단계 이벤트를 더 많이 기록하는 행동.
  • 없을 때전환 이벤트가 하나도 없으면 「ブログ・記事を読んでもらう」(어느 사이트나 「읽기」는 있다).
  • 업종그 행동에 딸린 업종 중 첫 번째(실제 출처가 있는 것).
  • 데모GA4가 없으므로 사이트 이름으로(이름에 media → 콘텐츠, 그 외 → 買う).
  • 알림보드 위 안내: 「まず数字を出すため、2つを仮で決めました（이유）」+ 「流れ ✎直す」「比べる業種 変える▾」「このままでよい」. 고르거나 「このままでよい」를 누르면 사라진다.

흐름 계산 규칙

  • 인원 = 그 이벤트를 기록한 사용자 수(totalUsers). 세션 수는 따로.
  • 화살표 % = 이번 단 ÷ 바로 앞 단. 막대 높이 = 온 사람 대비 %.
  • 단은 1–8개. 공통 시작 2단은 권장. 마지막 단 = 주전환.
  • 사이트가 다른 이벤트 이름을 쓰면 단에 그 이벤트를 고른다(속성마다 저장, 같은 속성의 다른 브라우저에도 적용).

판정 규칙

  • 칩범위 안 = 目安内, 범위 밖 좋은 쪽 = 良好, 범위 밖 나쁜 쪽 = 要注意. 출처 없음 = 基準なし(누르면 이유), 건수처럼 업계와 비교하지 않는 것 = 比べない.
  • 범위참여율 계열 ±7.5pt · CVR ±40% · 카트→구매 ±10pt.
  • 정의 일치엔게이지·이탈·주CVR은 선택한 업종 값. 퍼널 비율은 계산식이 같을 때만 비교.
  • 今見るべきこと目安에서 가장 먼 지표 최대 3개. 나쁜 것(要注意)을 먼저, 그다음 좋은 것.
  • 一番の課題いまの状態 세 번째 타일 = 주전환율이 아닌 지표 중 目安에서 가장 나쁜 것.
  • 업종 안내目安 폭 이상 벗어난 지표가 있거나 要注意가 2개 이상이면 「業種を変える▾」를 띄운다.
